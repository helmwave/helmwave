# v0.44.4

### **Breaking change!**

* [#1201](https://github.com/helmwave/helmwave/issues/1201) `wait` now takes a helm v4 strategy (`watcher`, `legacy`, `hookOnly`) — previous booleans are rejected: use `watcher` instead of `true` and `hookOnly` instead of `false` (@r3nic1e)

* [#1201](https://github.com/helmwave/helmwave/issues/1201) `recreate` is no longer applied: helm v4 removed the option behind it (@r3nic1e)

* [#1201](https://github.com/helmwave/helmwave/issues/1201) A configured `post_renderer` now also receives hook manifests, matching helm v4's default — set `post_render_strategy: nohooks` for the previous behavior (@r3nic1e)

### New feature

* [#1201](https://github.com/helmwave/helmwave/issues/1201) Build on the Helm v4 SDK: Helm 3 reaches EOL in November 2026. Based on the helmtide migration by @semx (@semx)

* [#1201](https://github.com/helmwave/helmwave/issues/1201) New release option `server_side_apply` (true/false/auto) controls helm v4 server-side apply (@r3nic1e)

* [#1201](https://github.com/helmwave/helmwave/issues/1201) New release option `force_conflicts` forces server-side apply changes against field-ownership conflicts (@r3nic1e)

* [#1201](https://github.com/helmwave/helmwave/issues/1201) New release option `post_render_strategy` (combined/separate/nohooks) controls how manifests are handed to the post_renderer (@r3nic1e)

### Other

* [#1201](https://github.com/helmwave/helmwave/issues/1201) `post_renderer` commands are now executed by helmwave itself, since helm v4 only supports plugin post-renderers (@r3nic1e)
